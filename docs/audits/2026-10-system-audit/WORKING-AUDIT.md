# ShelraCode forensic system audit

Started 2026-10-04. This directory records the current checkout, not the historical reference implementation. No claim of months-long reliability is admissible without a months-equivalent workload and independent correctness evidence.

## Method and completion criteria

Inspect the live path before product changes. Record baseline checks; reproduce failures in isolated fixtures; distinguish implementation evidence, deterministic fault injection, historical traces and live-model evidence. Fix reproducible critical defects with regression coverage, rerun the original probes and required checks. Report untested scenarios explicitly. Preserve unrelated working-tree changes. Use only free providers for any real-model runs. Never save credentials or raw private transcripts in evidence.

## Limits and changes to the experiment

- Initial concurrency timing evidence measured index counts; its worker accidentally used a non-enumerated topic type. That does not affect index writes, the measured operation, but is not evidence of readable recalled bodies. The corrected post-fix worker and dedicated regression use `architecture` and verify all 100 bodies as well.
- Initial deterministic probes overlapped the scripted memory evaluation. Absolute performance timings may include contention; the stderr comparison measures a single synchronous parser, not an end-to-end query latency improvement.
- Initial restricted execution blocked OpenRouter connectivity; later unrestricted execution succeeded. Environment failures are kept separate from product failures. Live tests use the free router and isolated state.
- A 75-second experiment budget is not proof of an infinite freeze. Changing free-router upstream models and three repetitions do not isolate model quality statistically.
- A third ladder ran after fair memory admission and Bun runner correction with a product fingerprint. A brief per-minute limit stopped it after 23 trials; a same-fingerprint resume reached 26 before the provider returned Limited. Failure-probe observation is explicit at levels 8–10; absent observation is not proof of instruction compliance or violation. Later model/persistence, Windows ownership, monotonic-clock and image-persistence follow-ups occurred afterward. A fresh latest-code live ladder requires a fresh label and recovered free quota; the completed intermediate ladder is retained.
- Not established: months-long production endurance, a full 3/5 real-provider agent load, native stacks for the remaining verification tail, sustained socket/FD/RSS trends, real Supabase fault behavior, interactive TUI load/cancellation or a malicious-repository exfiltration campaign. Source inspection is not runtime coverage. This prevents claiming the months-long reliability standard achieved.

- Optional manual cleanup of two task-owned preflight temporary folders was rejected before execution by automatic policy review with the reason `blocked by policy`. No deletion or bypass was attempted after that rejection; their current presence was not established. The fixtures used synthetic credentials.
