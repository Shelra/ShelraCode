## B. Retrieval-research literature (arXiv / peer-reviewed)

| # | Title | Author(s)/venue | Date | URL | Status | What it evidences |

| 8 | Lost in the Middle: How Language Models Use Long Contexts | Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang — TACL 2023 | submitted 2023-07-06, TACL-published 2023-11 | https://arxiv.org/abs/2307.03172 | VERIFIED (abstract-level) | Foundational finding: model accuracy on multi-document QA and key-value retrieval is highest when the relevant item is at the start or end of context, and "significantly degrades" when it is in the middle — the U-shaped curve, even for models built for long context |
| 9 | Context Rot: How Increasing Input Tokens Impacts LLM Performance | Chroma Research | 2025-07-14 | https://www.trychroma.com/research/context-rot | VERIFIED | 18 frontier models across Anthropic/OpenAI/Google/Alibaba tested on Needle-in-Haystack variants, LongMemEval, and a repeated-words task. | 10 | RULER: What's the Real Context Size of Your Long-Context Language Models? | Hsieh, Sun, Kriman, Acharya, Rekesh, Jia, Zhang, Ginsburg (NVIDIA) — COLM 2024 | 2024-04 | https://arxiv.org/abs/2404.06654 | SEARCH-ONLY (abstract/summary via search, not full HTML fetch) | 17 long-context models tested on 13 tasks; despite near-perfect vanilla needle-in-haystack scores, most show large performance drops as length grows, and only about half hold "satisfactory" performance at 32K tokens despite claiming larger windows — supports that advertised context length is not effective retrieval length |
| 11 | Long Context vs. RAG for LLMs: An Evaluation and Revisits | (authors not independently confirmed beyond arXiv listing) | submitted 2024-12-27 | https://arxiv.org/html/2501.01880 | VERIFIED | 3-phase study, 12 QA benchmarks (~19,188 → 13,628 questions after filtering). Long-context (LC) answered 56.3% correctly vs RAG's 49.0% overall; but the split is task-dependent: LC wins on Wikipedia-style fact lookup and self-contained narrative; RAG wins on dialogue-fragmented sources and open-ended "how/why" synthesis questions. | 12 | Retrieval-Augmented Code Generation: A Survey with Focus on Repository-Level Approaches | Tao, Li, Qin, Liu | v3 dated Oct 2025 (arXiv:2510.04905) | https://arxiv.org/html/2510.04905 | VERIFIED | Four-way taxonomy for code retrieval: lexical/sparse (BM25-style), dense/embedding (GraphCodeBERT, UniXcoder), graph-based (AST/call-graph/PDG-driven), hybrid (ReACC, CEDAR, RAP-Gen combine BM25 + dense). | 13 | When Retrieval Succeeds and Fails: Rethinking Retrieval-Augmented Generation for LLMs | (survey, arXiv:2510.09106) | 2025-10-10 | https://arxiv.org/html/2510.09106 | VERIFIED | RAG helps: knowledge-intensive domain-specific lookup, private/enterprise knowledge, fast-changing real-time knowledge. ## C. Agent-memory retrieval literature (context-pack relevance determination)

| # | Title | Author(s) | Date | URL | Status | What it evidences |
|---|---|---|---|---|---|---|
| 16 | Generative Agents: Interactive Simulacra of Human Behavior | Park, O'Brien, Cai, Morris, Liang, Bernstein — UIST 2023 | 2023 | https://dl.acm.org/doi/fullHtml/10.1145/3586183.3606763 | SEARCH-ONLY (summary via search, not independently fetched full text this pass) | Foundational relevance-determination formula for a memory-retrieval "context pack": `score = α_recency·recency + α_importance·importance + α_relevance·relevance` (all α=1 in the original implementation); recency/importance/relevance each min-max normalized to [0,1]; relevance = cosine similarity of memory embedding to query embedding; importance = LLM-assigned score; top-ranked memories fill the available context budget. Predates the mission's 2025–2026 evidence window but is the direct ancestor of subsequent (2025-2026) agent-memory retrieval-scoring papers found in search results (e.g. arXiv:2604.12007, arXiv:2606.12945 on memory-value/governance models), which were not independently fetched this pass and are not cited as load-bearing here |
| 17 | Zep: A Temporal Knowledge Graph Architecture for Agent Memory | (Zep/Graphiti team) | submitted 2025-01-20 (arXiv:2501.13956) | https://arxiv.org/html/2501.13956 | VERIFIED | Graph-based (temporal knowledge graph) memory retrieval beats both a full-context baseline and MemGPT on relevance/accuracy while cutting context size and latency sharply. Deep Memory Retrieval: Zep 94.8% vs MemGPT 93.4% vs full-conversation baseline 94.4% (gpt-4-turbo). LongMemEval: Zep 63.8%/71.2% accuracy (gpt-4o-mini/gpt-4o) vs full-context baseline 55.4%/60.2%, with average retrieved context of ~1.6k tokens vs ~115k tokens for full-context, and roughly 90% lower latency. This is a case where graph-structured, time-aware retrieval clearly outperforms both raw long-context stuffing and a prior memory system, for conversational/decision-style memory rather than code |
